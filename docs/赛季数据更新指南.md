# 超音速赛季数据更新指南

这套框架的原则是：比赛、积分榜、球员赛季信息只维护在
`data/seasons/<赛季>/`。网页通过 Backend API 自动读取，不需要修改 React
页面，也不要再把比赛数字写回 `frontend/src/data/mockData.ts`。

## 每个赛季有哪些文件

```text
data/seasons/赛季/
├── season.json      # 赛季名称和已确认总结
├── teams.json       # 标准队名、别名和队徽地址
├── matches.json     # 比分与超音速进球事件
├── standings.json   # 官方积分榜字段
└── players.json     # 球员身份、赛季资料和照片地址
```

所有 `team_id`、`player_id`、`match id` 都是稳定标识。已经使用后不要随意
改名，否则旧比赛会找不到对应球队或球员。

## 怎么新增一场比赛

1. 打开目标赛季的 `matches.json`，例如
   `data/seasons/26-27/matches.json`。
2. 在 `matches` 数组中复制一个同阶段的 match object。
3. 修改 `id`、`stage`、`round` 或 `leg`、主客队 ID、比分和 `scorers`。
4. 没有确认日期时让 `date` 保持 `null`，不要猜日期。
5. 确认主客队 ID 已存在于同赛季 `teams.json`。
6. 确认每个个人进球的 `player_id` 已存在于同赛季 `players.json`。

常规赛模板：

```json
{
  "id": "26-27-regular-01",
  "season": "26-27",
  "competition": "填写已确认赛事名称",
  "stage": "regular",
  "round": 1,
  "leg": null,
  "date": null,
  "home_team_id": "supersonic",
  "away_team_id": "opponent-team-id",
  "home_score": 0,
  "away_score": 0,
  "scorers": []
}
```

个人进球写法：

```json
{
  "type": "player",
  "player_id": "player-id",
  "player_name": "球员姓名",
  "goals": 1,
  "note": null
}
```

乌龙球写法：

```json
{
  "type": "own_goal",
  "goals": 1,
  "note": "只填写已确认备注"
}
```

乌龙球不要填写 `player_id`，否则会让维护者误以为这是个人进球。每场
`scorers` 的 goals 总和必须等于超音速在比分中的进球数。

季后赛半决赛使用 `stage: "playoff_semifinal"`，并填写 `leg: 1` 或
`leg: 2`；不要把它写成常规赛第 8、9 轮。

## 怎么新增球员或球员照片

新增球员时，只在目标赛季 `players.json` 的 `players` 数组增加一项。未知
字段使用 `null`，不要猜号码、位置、出场或助攻。

增加照片只需两步：

1. 把照片复制到 `frontend/public/assets/players/`，例如
   `frontend/public/assets/players/player-id.jpg`。
2. 在目标赛季 `players.json` 对应球员中修改：

```json
"photo_url": "/assets/players/player-id.jpg"
```

不需要修改 Component 或 CSS。网页图片加载失败时会自动显示姓名占位。
球员照片使用 `object-fit: cover`。

### 射手榜资格

球员的进球数不要写进 `players.json`，它会从 `matches.json` 自动统计。

若球员历史进球需要保留但不进入最终队内射手榜，设置：

```json
"scorer_table_eligible": false,
"scorer_table_exclusion_reason": "填写已确认原因"
```

不要删除他在比赛记录中的进球。需要审计全部历史进球球员时，可请求：

```text
GET /api/stats/scorers?season=25-26&show_all_scorers=true
```

## 怎么新增对手和队徽

先在目标赛季 `teams.json` 添加或找到该队。`name` 是网页统一显示的标准
名称，历史名称放入 `aliases`，比赛只引用稳定 `id`。

增加队徽只需两步：

1. 把图片复制到 `frontend/public/assets/teams/`，例如
   `frontend/public/assets/teams/youngsters.png`。
2. 在 `teams.json` 修改：

```json
"crest_url": "/assets/teams/youngsters.png"
```

没有队徽时保持 `crest_url: null`，网页会显示统一占位，不会生成假队徽。
队徽使用 `object-fit: contain`。

## 怎么更新积分榜

只修改目标赛季的 `standings.json`。目前允许的官方字段是：

- `rank`
- `team_id`
- `points`
- `goal_difference`
- `goals_for`

不要根据比分自行补充胜、平、负、比赛场次、失球数。`rank` 必须唯一，
`team_id` 必须存在于同赛季 `teams.json`。

## 怎么开始新赛季

1. 复制上一赛季目录作为结构参考，建立新目录，例如 `data/seasons/26-27/`。
2. 修改 `season.json` 的 `id` 和 label。
3. 清空 `matches.json` 的 `matches` 数组。
4. 清空 `standings.json` 的 `standings` 数组。
5. 清空未确认的参赛队和球员；只把已经确认的新赛季内容写进
   `teams.json`、`players.json`。
6. 不要沿用上一赛季的号码、位置、比赛或积分榜事实。

当前 26-27 已经是空框架，不含虚构比赛、球员或积分榜。

## 怎么验证自己没填错

在项目根目录运行：

```powershell
python scripts/validate_season_data.py --season 26-27
python -m pytest tests/test_season_data.py -v
```

验证脚本会检查 ID 唯一性、球队/球员引用、每场进球事件与比分、乌龙球、
射手榜资格和积分榜排名。对于 25-26，它还会核对 7 场常规赛、23 个常规赛
进球、2 场季后赛以及最终射手榜第一名。

网页开发环境还需要启动 Backend：

```powershell
python -m uvicorn backend.main:app --reload
```

然后在 `frontend/` 运行 `npm run dev`。部署到不同 API 地址时设置
`VITE_API_BASE_URL`，无需修改页面代码。
